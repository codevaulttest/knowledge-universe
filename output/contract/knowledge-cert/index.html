知识确权接口契约

这份契约覆盖确权徽章、申请确权（实名认证 + 确权兑换两步）、版本记录、认证证书详情、个人主页「确权」筛选这几处前端页面。

接口来源
本模块 Apifox 暂无对应目录。下表接口与字段是前端按已定规则提出的建议，路径与字段名由后端确定。
现行规则
帖子当前版本满 100 赞后可确权，作者既可以手动申请，也可以设置满 N 赞（不低于 100）自动确权。首次申请前需通过实名审核。认证由平台发出并铸造上链，按帖子版本绑定，人工核查后可撤销，链上保留撤销记录。
怎么用
第 7 节是前端期望的接口返回，改名后可直接录入；第 6 节汇总所有待确认项。
最近更新
2026-09-30 首次发布；补充实名有效期与重新认证的待确认项，新增自动确权规则（2.4）。
已有 接口已提供已确认 双方已对齐建议新增 字段名可由后端定待确认 需要后端回复

2. 状态判定

2.1 认证状态

一条认证对应「一个帖子的一个版本」。前端按 certStatus 显示徽章：

状态certStatus含义前端显示
确权中1已提交申请、链上铸造未完成灰色「确权中」徽章，只有作者本人看得到
已确权2铸造完成蓝色「已确权」徽章，所有人可见，点开是证书
已撤销3人工核查后撤销红色「已撤销」徽章，证书显示撤销原因和时间

待确认 铸造失败：链上铸造失败时返回什么状态？前端目前只有上面三种。如果失败可重试，建议单独一个取值，前端显示「铸造失败，可重新申请」。

2.2 按版本绑定

认证绑定申请时的版本号。作者编辑有认证的帖子时，旧版本连同它的认证一起保留，新内容成为下一个版本：

情况帖子 version当前版本的认证前端显示
从没申请过确权1无无徽章；编辑不生成新版本，不弹提示
当前版本已确权如 1certStatus=2「已确权」；编辑前提示会生成新版本
确权后被编辑过2无灰色「v1 已确权」，点开是 v1 的证书；当前版本赞数从 0 重新累计
新版本又申请了2certStatus=1 或 2按当前版本的状态显示；v1 的认证仍可在版本记录里查看

待确认 版本号与赞数由谁维护：前端建议后端在帖子上维护 version（从 1 开始）和 versionStartLikes（该版本开始时帖子的累计赞数）。当前版本赞数 = 帖子累计赞数 − versionStartLikes，满 100 才能申请。帖子列表和详情仍返回累计赞数，前端照常显示。只有申请过确权的帖子（任一状态）在编辑保存时才归档旧版本、版本号 +1。

2.3 实名认证状态

状态realNameStatus前端显示
未提交0申请流程第一步：选择证件类型、上传证件照、提交
审核中1第一步显示「实名资料审核中」，不能进入兑换那一步
已通过2申请流程直接从第二步（确权兑换）开始

实名做一次，之后每次申请确权直接从兑换那一步开始，不再要求上传证件。

待确认（4 项） 一、审核被驳回是否单独一个状态、是否返回驳回原因，能否重新提交；二、审核时效，前端文案不写时长，只说审核完成后会通知作者；三、审核结果用什么通知作者（站内信 / 推送）；四、实名是否会失效、需要重新认证：证件过期、作者更换证件、风控要求复核时状态如何变化，是否需要一个「需重新认证」的取值，以及此时已申请的认证是否受影响。

2.4 自动确权

作者可以设置「满 N 赞自动确权」，由服务端到点发起，不需要作者每次打开申请流程。规则如下：

规则说明
阈值下限N 不得小于 100，作者只能往上调
授权单价开启时记录当时的确权费单价，之后按该单价扣费
调价确权费一经调整，自动确权立即暂停并通知作者；未重新授权前不扣费、不铸造
倒计时帖子达到阈值时先通知「24 小时后自动确权」，到点才扣费铸造
倒计时期间编辑作者改了内容则顺延重新计时，并按新版本重新判断赞数是否达标
作者取消倒计时期间可取消这一次，帖子回到手动申请状态
暂停期间达标挂起等待，作者重新授权后补铸，不设过期时间
余额不足标记为挂起，待余额补足后继续，不作废、不设过期时间

待确认（5 项） 一、倒计时与挂起任务由谁驱动（服务端定时任务），前端只读展示是否可行；二、挂起任务的状态取值，以及前端在帖子上如何区分「倒计时中」和「挂起中」；三、重新授权后补铸是一次性全部发起还是分批，作者能否先看清单再确认；四、实名未通过或被撤销时自动确权如何处理；五、自动确权的扣费通知与账单记录走哪条链路。

这条路径前端原型尚未实现，字段对照待接口方案确定后补充。

3. 字段对照

3.1 帖子列表 / 帖子详情 → 确权信息

帖子对象上补充以下字段，前端据此显示徽章、版本号和申请入口：

字段类型前端用途状态
versionint当前版本号，大于 1 时显示「v2 · 已编辑」并可点开版本记录建议新增
versionLikesint当前版本获得的赞数，判断是否满 100 可申请；后端也可只返回 versionStartLikes，由前端相减建议新增
certIdstring当前版本的认证 ID，查证书详情用；没有则为空建议新增
certStatusint当前版本的认证状态，见 2.1；没有认证时为 0建议新增
lastCertVersionint该帖子最近一个已确权的版本号；当前版本没有认证时显示「vN 已确权」建议新增
lastCertIdstring上一条的认证 ID，点徽章进入该版本的证书建议新增
canApplyCertbool是否显示「申请确权」入口；后端不返回时，前端按「本人 + versionLikes ≥ 100 + 当前版本无认证」自行判断建议新增

「确权中」徽章只对作者本人显示，前端已按作者判断，接口可以对所有人返回同样的数据。

3.2 GetMyCertList → data

个人主页「确权」筛选一次取两部分：已申请的认证（含已撤销）和可申请的帖子。

字段类型前端用途状态
certCountint筛选标签旁的数量建议新增
items[].postIdstring帖子 ID，列表里渲染整张帖子卡片建议新增
items[].certIdstring认证 ID；可申请但还没申请的帖子为空建议新增
items[].certStatusint认证状态，见 2.1建议新增
items[].versionint认证对应的版本号建议新增
items[].canApplybool为 true 时卡片上方显示「已满 100 赞，可申请确权」和申请按钮建议新增

列表为空时前端显示空态「还没有知识确权认证」。帖子本身的内容仍走帖子接口或由本接口带上，取决于后端哪种方便，请告知。

3.3 GetRealNameStatus → data

字段类型前端用途状态
realNameStatusint见 2.3，决定申请流程从哪一步开始建议新增
submitTimedatetime审核中时展示提交时间建议新增
rejectReasonstring驳回时展示原因；没有驳回状态则不需要待确认

3.4 SubmitRealName

请求参数建议：idType（1 身份证 / 2 护照）、idImages（证件照，身份证两张、护照一张）。

待确认（3 项） 一、证件照走哪个上传接口、传 URL 还是 base64；二、除证件照外是否还要姓名、证件号码、人脸核验，前端原型目前只有证件类型和证件照两项；三、提交后能否修改或撤回。

返回只需 result 和 message，成功后前端把状态置为审核中并提示「资料已提交，审核通过后会通知你」。

3.5 ApplyCert

请求参数建议：postId、version（前端拿到的当前版本号，供后端校验版本未变）、payWallet（兑换使用的 PB 钱包）。

响应字段前端用途状态
certId新建的认证 ID，用于跳转证书页建议新增
certStatus提交后应为 1（确权中）建议新增
costPb实际扣除的 PB，用于提示与对账建议新增
supFee实际扣除的 SUP 手续费建议新增

待确认（4 项） 一、确权兑换费金额，前端原型用的是占位值 500 PB；二、可用哪些 PB 钱包（原型暂按可提取 PB 和链上 PB）；三、手续费是否与竞拍一致，按万分之一收 SUP；四、申请后铸造失败或认证被撤销时费用是否退回。

扣费与创建认证需在同一次请求内完成，前端不做两步提交。成功后前端刷新钱包余额和确权列表。

4. 错误约定

沿用竞拍的约定：同一接口的各种失败共用一个 result，通过 message 区分，前端直接显示 message。result 请避开 -2、-7、-8、-9、-11、-16，前端请求层会把这几个值当作登录失效。页面有简中、繁中、英文，message 方便的话按请求语言返回。

场景规则
赞数不足当前版本赞数小于 100 时拒绝申请
当前版本已有认证确权中、已确权、已撤销都算已有，同一版本不能重复申请
版本已变化请求里的 version 与服务端当前版本不一致时拒绝，前端刷新后重新申请
实名未通过realNameStatus 不是已通过时拒绝申请
PB 余额不足所选钱包可用 PB 小于兑换金额
SUP 不足站内 SUP 小于手续费；是否收手续费待确认（见 3.5）
非本人只有作者本人能为自己的帖子申请确权

5. 通用约定

  • 时区：所有时间字段为北京时间，不带时区标记，前端按 +08:00 解析。
  • 金额单位：兑换金额单位为 PB，手续费单位为 SUP。
  • 认证主体：认证由平台发出，前端没有作者签名环节，申请接口不带任何签名参数。
  • 徽章数据来源：确权信息随帖子一起返回（见 3.1），前端不为每条帖子单独请求确权接口。
  • 证书详情：已确权和已撤销的证书对所有人可见；确权中的认证只有作者本人能看到入口。

待确认 认证归属：链上 NFT 由平台钱包持有还是记在作者的托管地址？证书上的「认证作者」目前显示作者昵称，如果要展示持有地址请提供对应字段。

6. 待确认汇总

  1. 接口路径与字段命名，以及本模块是否在 Apifox 建目录（第 1 节）。
  2. 铸造失败返回什么状态、能否重试（2.1）。
  3. 版本号与每版赞数由后端维护的方案是否可行（2.2）。
  4. 实名审核是否有驳回状态与驳回原因、审核时效、结果如何通知（2.3）。
  5. 实名是否会失效、需要重新认证，以及重新认证期间已有认证是否受影响（2.3）。
  6. 证件照上传方式，以及除证件照外还需要哪些实名资料（3.4）。
  7. 确权兑换费金额、可用钱包、是否收 SUP 手续费、失败或撤销是否退费（3.5）。
  8. 区块浏览器交易页地址前缀（3.6）。
  9. 撤销原因代码清单，撤销是人工还是有自动规则（3.7）。
  10. 链上 NFT 的持有方，证书上是否展示持有地址（第 5 节）。
  11. 自动确权的倒计时与挂起任务如何驱动、状态如何返回、补铸怎么发起（2.4）。

产品侧已定：当前版本满 100 赞可确权（手动申请或按作者设置的阈值自动确权，阈值不低于 100）、认证按帖子版本绑定、新版本赞数从 0 重新累计、认证由平台发出无需作者签名、首次申请前需通过实名审核、自动确权按开启时的单价扣费且调价后须重新授权、到达阈值后倒计时 24 小时再铸造、撤销后链上保留撤销时间和原因、赞数回落不撤销认证。

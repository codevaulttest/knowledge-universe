# 页面地图 + 候选提问单

**这份文件有两个用途，别混淆：**
1. **页面地图**（下方"页面清单"）——审计第 2 步核验代码时，用它定位每个功能该去哪个文件看。这是事实。
2. **候选提问单**（下方"标准功能清单"）——审计第 3 步用它勾用户记忆。**这些是要问用户的问题，不是缺口、不是待办。** 只有用户回"要"，某一项才升级成待办。raw_context 里没出处的功能，永远停在这一层，不准直接列进"确认待办"。

清单按"页面 × 标准功能"组织。

## 页面清单（src/pages + 关键组件）

| 页面 | 文件 | 职责 |
|---|---|---|
| 首页信息流 | `FeedPage.tsx` | 帖子流、下拉刷新、频道切换 |

| 发帖 | `ComposePage.tsx` | 文字/图片/视频、频道、可见比例、小黄车 |
| 个人主页 | `ProfilePage.tsx` | 头像、昵称、关注/粉丝、编辑资料、订单入口 |
| 频道 | `ChannelPage.tsx` | 频道详情、订阅档位 |
| 通知/互动中心 | `ActivityPage.tsx` | 点赞/评论/关注/系统通知 |
| 私信 | `DmPage.tsx` | 会话列表、聊天 |
| 搜索 | `SearchPage.tsx` | 搜帖/人/频道、热搜 |
| 商城/小黄车 | `ShopPage.tsx` `ShopItemPage.tsx` `OrdersPage.tsx` | 商品、下单、地址、订单 |

## 定级参考（ROI × 紧急度）

- **P0**：改动小、见效快、或止损（领导反复问的、明显体验瑕疵）
- **P1**：中等成本、无外部依赖、能独立上线（如 bio）
- **P2**：大改、牵扯规则或后端、领导已说"后续"（如二级评论盖楼、频道会员体系）

## 项目特有约定（审计时一并检查）

- 所有可见文字 ≥ 12px、对比度 ≥ 4.5:1（AGENTS.md 硬规则）
- 颜色/间距/圆角必须走 `--ku-*` token，禁硬编码、禁借用主 App 蓝紫色 token
- 纯前端 mock，无后端；缺口只看 UI/UX 层，不含后端接口
- i18n 迭代期只维护 zh-CN + en，其余 9 语言定稿后批量补
